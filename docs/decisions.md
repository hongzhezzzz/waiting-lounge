- 2026-05-07: **Brain Bet 2.0 critical engineering invariants** (per `docs/research/game-mechanics.md`). (1) Bets MUST close before answers are revealed — strict per-round phase machine `reveal → bet → answer → showdown`. The current `handleAction()` accepts answer events at any time and must be replaced with phase guards. If a client can peek at the answer and *then* bet, the game collapses to "always bet when correct" and there's no game theory left. (2) Every round type must support a Fold action — a low-stack player must never be auto-bankrupted; they must be able to surrender only the 50-chip forced ante, not their whole stack. Trivia rounds get a fold too ("I know the answer but want to save chips" is a valid play). (3) Running-stack chips are NOT user account points — they live in `runner.state` only. `transferPoints.ts` (`chargeAntes`, `settleGame`) does not change. The runner picks `winnerSocketId` from chip lead at end-of-match and passes it to `settleGame()` as today. Crash recovery / refund / cold-start path keep working with zero modification because the chip stack never touches Postgres.
